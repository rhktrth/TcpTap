# ADR-0001: JRE 8互換の小規模CLIとして実装を閉じる

## 状態

採用

## 背景

TcpTap は、ネットワーク作業時に一時的に配置して使える軽量な TCP 中継ツールを目的とします。導入のためにアプリケーションサーバー、コンテナ実行環境、ネイティブライブラリ、複雑な設定基盤を要求すると、この用途に対して運用コストが大きくなります。

JRE 8 で実行できることは、配置可能な環境を広く保つための明示要件です。今後もバイトコードと Java SE API の互換性を維持します。

一方、CLI の解析、使用方法の生成、オプションの基本検証は一般化された問題であり、独自パーサーを保守する価値は低いと判断します。

## 決定

- JRE 8 を最低動作環境とする。
- 本体コードは、Java 8 の言語仕様と Java SE 8 API の範囲で実装する。
- CI は Java 8 でビルド、テスト、実行可能 JAR の起動を検証する。
- 新しい Java 実行環境でも、同じテスト一式と実行可能 JAR を検証する。
- 中継／キャプチャ処理は Java SE 標準ライブラリで実装する。
- CLI の解析、使用方法生成、基本的な入力検証には Java 8 対応の picocli を利用する。
- picocli は実行可能 JAR に同梱し、利用者に追加の依存ライブラリ配置を要求しない。
- Maven をビルドの正本とし、プラグインのバージョンとビルドツールの最低バージョンを明示する。
- 実行形態は単一の実行可能 JAR を基本とする。
- その他のフレームワークや依存ライブラリは、標準ライブラリまたは既存の依存ライブラリでは満たせない現在の要件がある場合だけ追加する。
- IDE 固有設定はリポジトリの正本にしない。

## 影響

JRE 8 があれば実行できる配布形態を維持しつつ、CLI パーサーやヘルプ表示の独自実装を削減できます。CLI 用の依存ライブラリは増えますが、単一 JAR へ同梱するため、利用者の導入手順は増えません。

Java 8 の標準スレッドを使うため、仮想スレッドなどの新しい実行環境機能には依存できません。大量接続向けプロキシではなく、診断・一時中継ツールとして、単純さと配置互換性を優先します。

## 見直し条件

- JRE 8 互換性の維持が、セキュリティ、保守性、または中心機能の実現に対する明確な障害になる場合。
- CLI 用の依存ライブラリが JRE 8 対応を終了する場合。
- TcpTap の用途が大量接続向けプロキシへ変わり、1セッションにつきスレッドを割り当てる方式が要件を満たさなくなる場合。
